# Resume Builder Rules Engine — Universal README

> Use this document as the product rulebook for generating resumes for any role, industry, seniority, and country format.  
> Goal: create resumes that are truthful, role-targeted, ATS-readable, recruiter-friendly, and conversion-focused.

---

## 1. Core Resume Philosophy

Every resume generated by the product must follow these principles:

1. **Truth first**
   - Never invent jobs, degrees, companies, certifications, metrics, salary, awards, clients, or tools.
   - AI may rephrase, organize, and strengthen wording, but must not fabricate experience.
   - If a metric is missing, use non-fabricated impact language such as:
     - `improved process efficiency`
     - `reduced manual effort`
     - `supported faster delivery`
     - `contributed to quality improvement`
   - Ask for the metric instead of guessing when it materially changes the claim.

2. **Job-targeted**
   - A resume should be generated against a target role, job description, or role family.
   - The resume must prioritize the most relevant experience, skills, tools, projects, certifications, and achievements.
   - A generic resume is acceptable only when no job description is provided.

3. **ATS-readable**
   - Use simple structure.
   - Avoid images, icons, text boxes, complex tables, multi-column layouts, graphics, and headers/footers for critical content.
   - Use standard section headings.
   - Use keyword alignment from the job description.
   - Keep dates, titles, companies, and locations easy to parse.

4. **Recruiter-friendly**
   - Put the strongest information in the top half of page one.
   - Use clear job titles, quantified achievements, tools, business impact, and domain context.
   - Use short bullet points.
   - Avoid paragraphs where bullets work better.

5. **Human + machine balanced**
   - ATS needs keywords.
   - Recruiters need proof.
   - Hiring managers need relevance.
   - Therefore each resume must combine:
     - exact role keywords
     - measurable achievements
     - action verbs
     - context
     - readable formatting

## 3. Resume Output Types

The product should support these resume types:

1. **ATS Resume**
   - Plain, clean, single-column.
   - Best for online applications.
   - No graphics or icons.
   - Highest parsing accuracy.

2. **Modern Professional Resume**
   - Clean design with mild styling.
   - Safe for human review.
   - Should still be ATS-compatible.

3. **Creative Resume**
   - For design, media, branding, visual roles.
   - Should be accompanied by a separate ATS version.

4. **Executive Resume**
   - 2 pages acceptable.
   - Focus on leadership, P&L, strategy, transformation, scale, board-level outcomes.

5. **Academic CV**
   - Longer format allowed.
   - Includes research, publications, teaching, grants, conferences.

6. **International CV**
   - Adjust based on target country.
   - May include language skills, visa/work authorization, region-specific sections.

7. **Fresher/Student Resume**
   - Focus on education, projects, internships, skills, certifications, achievements.

8. **Career Change Resume**
   - Emphasize transferable skills and relevant proof.
   - Use hybrid format.

9. **Freelancer/Consultant Resume**
   - Focus on clients, projects, outcomes, tools, industries, testimonials if available.

10. **Government/Public Sector Resume**
   - Clear chronology.
   - Eligibility details.
   - Education and experience aligned to official criteria.

## 5. Mandatory Fields by Section

### 5.1 Header

Mandatory:
- Full name
- Phone number
- Email address
- City, State/Region, Country
- LinkedIn or portfolio if relevant

Optional:
- LinkedIn
- GitHub
- Portfolio
- Personal website
- Work authorization
- Relocation preference
- Notice period, only if explicitly useful in target market

Do not include by default:
- Full street address
- Date of birth
- Marital status
- Religion
- Caste
- Aadhaar/passport/government ID
- Salary
- Parent names
- Photo, unless country/role expects it and user approves

Validation:
- Email must look professional.
- Phone must include country code for international applications.
- Links must be clickable and clean.
- Do not display long raw URLs if a clean label is possible.

### 5.2 Professional Summary

Mandatory for:
- Experienced professionals
- Senior roles
- Executive roles
- Career changers
- Freelancers
- International resumes

Optional for:
- Freshers, where `Objective` may work better.

Rules:
- 2–4 lines maximum.
- Mention target role alignment.
- Include years of experience only if true.
- Include 3–5 strongest skill/domain keywords.
- Include 1 measurable or high-value impact area if available.
- Avoid generic claims like `hard-working`, `self-motivated`, `quick learner` unless backed by proof.

Good structure:
`[Role/title] with [X years/experience type] in [domain]. Skilled in [top skills/tools]. Proven ability to [achievement/impact]. Seeking/targeting [role/outcome].`

Examples:
- `QA Automation Engineer with 3+ years of experience building Selenium, Playwright, and API test automation frameworks for web applications. Skilled in Java, JavaScript, REST API testing, CI/CD integration, and defect lifecycle management. Improved regression coverage and reduced manual testing effort through scalable automation suites.`
- `Entry-level Data Analyst skilled in SQL, Excel, Python, Power BI, and data visualization. Built academic and personal projects involving sales dashboards, data cleaning, and business insights. Seeking to apply analytical thinking and reporting skills in a data-driven business environment.`

### 5.3 Objective

Use for:
- Freshers
- Students
- Internships
- Career switchers
- Government exam resumes
- Academic applications

Rules:
- 1–2 lines.
- Must be specific to target role.
- Avoid vague phrases.
- Mention skills and value.

Example:
`Detail-oriented Computer Science graduate seeking a Junior Software Developer role to apply JavaScript, React, Node.js, and database skills in building reliable web applications.`

### 5.4 Skills

Mandatory:
- Hard skills
- Tools/platforms
- Role-specific skills

Optional:
- Soft skills
- Languages
- Domain skills

Rules:
- Use categories for readability.
- Include exact keywords from the job description if truthful.
- Include both acronym and full form when useful:
  - `Search Engine Optimization (SEO)`
  - `Customer Relationship Management (CRM)`
  - `Application Programming Interface (API)`
- Do not stuff unrelated keywords.
- Do not list skills the user cannot discuss in an interview.
- Prioritize 12–30 relevant skills depending on seniority.

Recommended categories:
- Programming Languages
- Frameworks/Libraries
- Databases
- Cloud/DevOps
- Testing Tools
- Data/Analytics
- AI/ML
- Design Tools
- Marketing Tools
- Sales Tools
- Finance Tools
- Project Management
- Domain Knowledge
- Soft Skills
- Languages

### 5.5 Work Experience

Mandatory for experienced users:
- Job title
- Company name
- Location
- Start date
- End date or Present
- 3–6 bullets per role

Rules:
- Reverse chronological order.
- Most recent role should have the most detail.
- Use 3–6 bullets for recent roles.
- Use 1–3 bullets for older or less relevant roles.
- Start bullets with action verbs.
- Avoid first-person language.
- Do not write full paragraphs.
- Include tools, scale, stakeholders, and impact.
- Quantify when possible.

Bullet formula:
`Action Verb + What You Did + How/Tools/Method + Result/Impact + Scope`

Examples:
- `Built a Playwright automation framework covering smoke and regression test cases, reducing repeated manual validation effort across weekly releases.`
- `Managed a sales pipeline of 120+ accounts using Salesforce, improving lead follow-up consistency and supporting monthly revenue targets.`
- `Analyzed customer churn trends using SQL and Power BI, identifying retention opportunities for high-risk customer segments.`

### 5.6 Projects

Mandatory for:
- Freshers
- Students
- Tech roles with limited experience
- Data/AI roles
- Design/product roles
- Career switchers
- Freelancers

Fields:
- Project name
- Role
- Tech/tools used
- Problem solved
- Key features/responsibilities
- Outcome/result
- Link, if available

Rules:
- Use 2–4 strong projects.
- Prioritize projects relevant to target job.
- Include deployed links/GitHub when possible.
- Explain business/user problem, not only technology.

Project bullet formula:
`Created/Built/Designed/Developed + project type + using tools + to solve problem + result/features`

### 5.7 Education

Mandatory:
- Degree/qualification
- Institution name
- Location
- Graduation year or dates
- Field/specialization

Optional:
- GPA/percentage if strong or required
- Relevant coursework
- Academic honors
- Thesis/dissertation
- Study abroad
- Major projects

Rules:
- Freshers: education can appear above experience/projects.
- Experienced professionals: education usually appears after experience.
- Do not include school details if user has significant higher education and experience unless relevant.
- Include marks only if strong or required by market.

### 5.8 Certifications

Fields:
- Certification name
- Issuing organization
- Date earned
- Expiry date if applicable
- Credential ID/link if available

Rules:
- Put highly relevant certifications near skills or education.
- Do not include expired certifications unless still useful and clearly marked.
- Avoid weak/unrelated certifications that dilute focus.

### 5.9 Achievements / Awards

Use when:
- Quantifiable achievements exist.
- User has competitions, scholarships, company awards, sales awards, academic rank, hackathons.

Rules:
- Include what, issuer, date/year, context, ranking/scale if available.
- Prefer measurable achievements.

Example:
`Won 1st place among 80+ teams in college hackathon for building a real-time attendance automation system.`

### 5.10 Publications / Research

Use for:
- Academic
- Research
- Healthcare
- Legal
- Scientific
- Policy
- Data/AI research roles

Fields:
- Title
- Authors
- Journal/conference
- Date/year
- DOI/link
- Summary if needed

### 5.11 Languages

Use when:
- Target role is international, customer-facing, teaching, hospitality, healthcare, support, sales, or translation.
- Mention proficiency:
  - Native
  - Fluent
  - Professional working proficiency
  - Conversational
  - Basic

### 5.12 References

Default:
- Do not include references on standard resumes.

Use only when:
- Employer asks.
- Academic CV expects it.
- Certain countries or public sector formats expect it.

Safe phrase:
`References available upon request.`

## 6. Resume Length Rules

| Candidate Type | Recommended Length |
|---|---|
| Student / Fresher | 1 page |
| 0–5 years experience | 1 page |
| 5–10 years experience | 1–2 pages |
| 10+ years experience | 2 pages acceptable |
| Executive | 2 pages usually acceptable |
| Academic CV | No strict limit |
| Medical/Research CV | No strict limit if publications and credentials matter |
| Government detailed format | Follow official instructions |

Rules:
- Do not force a senior/executive resume into one page if it loses important achievements.
- Do not create a two-page resume for a fresher unless there is exceptional project/research depth.
- Prioritize relevance over completeness.

## 7. Formatting Standards

### 7.1 ATS-Safe Formatting

Use:
- Single-column layout
- Standard fonts
- Standard section headings
- Simple bullet points
- Clear dates
- Plain text-friendly structure
- Consistent spacing

Avoid:
- Tables for core content
- Text boxes
- Headers/footers for name/contact
- Images/icons for contact details
- Progress bars
- Skill rating stars
- Fancy graphics
- QR-only portfolio access
- Important content in sidebars
- Complex multi-column layouts
- Unusual fonts
- Underlining
- Excessive color
- Abbreviations without full form

### 7.2 Font Rules

Recommended fonts:
- Calibri
- Arial
- Times New Roman
- Cambria
- Georgia
- Helvetica
- Aptos

Font size:
- Body: 10–12 pt
- Name: 16–22 pt
- Section headings: 11–14 pt

### 7.3 Margins and Spacing

- Margins: 0.5–1.0 inch
- Line spacing: readable, not cramped
- Use enough white space
- Keep section order logical

### 7.4 Dates

Accepted formats:
- `Jan 2022 – Present`
- `01/2022 – Present`
- `2022 – Present`

Rules:
- Be consistent across entire resume.
- Use `Present` for current roles.
- Do not hide gaps by using only years unless user chooses and it is acceptable.

### 7.5 File Format

Default export options:
- `.docx` for ATS upload compatibility
- `.pdf` for direct email/human sharing
- `.txt` for ATS debug preview
- `.json` for product data storage

Rules:
- If employer specifies a format, follow that.
- For ATS-heavy workflows, provide `.docx` and `.pdf`.
- Ensure generated PDFs preserve selectable text.

### 7.6 File Naming

Recommended:
`FirstName_LastName_TargetRole_Resume.pdf`

Examples:
- `Priya_Sharma_QA_Automation_Engineer_Resume.pdf`
- `Rahul_Patil_Data_Analyst_Resume.docx`

Avoid:
- `resume_final_final.pdf`
- `mycv.pdf`
- `newresume123.pdf`

## 8. ATS Tracker Rules

### 8.1 ATS Compatibility Checklist

The generated resume passes ATS rules only if:

- [ ] Contact details are plain text.
- [ ] Section headings are standard.
- [ ] Work experience is reverse chronological.
- [ ] Dates are consistent.
- [ ] Job titles and company names are clearly separated.
- [ ] No important information is inside images.
- [ ] No critical information is inside headers/footers.
- [ ] No complex tables or text boxes are used.
- [ ] File is PDF or DOCX unless employer asks otherwise.
- [ ] Keywords from the job description are included naturally.
- [ ] Acronyms and long-form versions are included where useful.
- [ ] Skills are not hidden in graphics/rating bars.
- [ ] Bullet points are readable as plain text.
- [ ] Resume avoids keyword stuffing.
- [ ] Resume content is truthful.

### 8.2 ATS Score Formula

Use a 100-point scoring system.

| Category | Weight |
|---|---:|
| Contact completeness | 5 |
| Section completeness | 10 |
| ATS formatting safety | 20 |
| Keyword match | 20 |
| Experience relevance | 15 |
| Achievement/impact strength | 15 |
| Skills relevance | 10 |
| Grammar/readability | 5 |

Score interpretation:
- 90–100: Excellent
- 80–89: Strong
- 70–79: Good but needs tailoring
- 60–69: Weak for competitive roles
- Below 60: Needs major improvement

### 8.3 ATS Keyword Match Logic

Extract from job description:
1. Job title
2. Required skills
3. Preferred skills
4. Tools/platforms
5. Certifications
6. Domain keywords
7. Methodologies
8. Soft skills
9. Years of experience
10. Education requirements
11. Responsibilities
12. Deliverables
13. Industry terms
14. Compliance/regulatory terms
15. Location/work mode

Classify keywords:
- Must-have
- Nice-to-have
- Tools
- Domain
- Action verbs
- Certifications
- Soft skills
- Seniority indicators

Match rules:
- Exact match is strongest.
- Synonym match is useful but weaker.
- Acronym + full form is strongest.
- Contextual use inside experience bullets is stronger than only listing in skills.
- Repeated natural usage is good.
- Keyword stuffing is bad.

Example:
If JD says:
`Experience with REST APIs, Selenium, Java, CI/CD, Agile, and defect tracking using Jira.`

Resume should include truthful phrases such as:
- `REST API testing`
- `Selenium WebDriver`
- `Java`
- `CI/CD pipeline`
- `Agile/Scrum`
- `Jira defect tracking`

### 8.4 Keyword Density Rules

- Do not target an artificial density percentage.
- Use each critical keyword at least once if truthful.
- Use top 5–8 must-have keywords in:
  - summary
  - skills
  - experience/projects
- Avoid repeating the same keyword unnaturally more than 3–5 times.
- Prioritize context over frequency.

### 8.5 ATS Failure Reasons

Reject or warn if:
- Missing email or phone.
- Missing work dates.
- Missing education.
- Resume has only paragraphs and no bullets.
- Resume has no target role.
- Resume has no skills section.
- Important data is in images or icons.
- Resume uses columns/tables heavily.
- Resume does not include job description keywords.
- Resume contains fake or unsupported claims.
- Resume is too long for career stage.
- Resume contains spelling errors in tools/technologies.

## 9. AI Keyword Engine

### 9.1 Keyword Extraction Pipeline

When a job description is provided:

1. Clean text.
2. Detect language.
3. Detect target role.
4. Detect seniority.
5. Detect industry.
6. Extract repeated terms.
7. Extract required qualifications.
8. Extract preferred qualifications.
9. Extract tools and technologies.
10. Extract verbs from responsibilities.
11. Extract compliance/certification requirements.
12. Extract measurable outcome terms.
13. Extract soft skills.
14. Group into keyword categories.
15. Compare against user profile.
16. Mark:
    - present
    - missing but user may have
    - missing and should not be added unless user confirms
17. Generate clarification questions for missing critical keywords.

### 9.3 Keyword Safety Rules

Allowed:
- Add keywords already present in user experience.
- Rephrase user experience using job description terminology.
- Add full-form/acronym versions.
- Move relevant skills higher.
- Ask user if they have missing must-have skills.

Not allowed:
- Add tools the user never used.
- Add certifications not earned.
- Add fake years of experience.
- Add fake leadership or team size.
- Add fake revenue metrics.
- Hide keywords in invisible text.
- Stuff keywords in unnatural lists.

## 13. Bullet Writing Rules

### 13.1 Bullet Structure

Good bullet:
`Action + Task + Tools/Methods + Result + Context`

Poor bullet:
`Responsible for testing application.`

Better:
`Automated regression test cases using Selenium and TestNG, improving release validation speed and reducing repetitive manual testing.`

### 13.2 Bullet Length

- Ideal: 1–2 lines.
- Avoid bullets longer than 3 lines.
- Use 3–6 bullets for recent roles.
- Use fewer bullets for old roles.

### 13.3 Bullet Quality Checklist

Each bullet should answer at least 2–3 of these:
- What did the user do?
- How did they do it?

## 15. Tailoring Rules

### 15.1 Resume Tailoring Process

For every target job:

1. Parse job description.
2. Identify target title.
3. Identify mandatory skills.
4. Identify preferred skills.
5. Identify tools.
6. Identify seniority.
7. Identify responsibilities.
8. Identify industry/domain.
9. Compare against user profile.
10. Reorder sections based on relevance.
11. Rewrite summary for the role.
12. Reorder skills based on JD priority.
13. Rewrite bullets to include truthful matching keywords.
14. Add missing-but-true relevant projects/certifications.
15. Remove irrelevant details.
16. Generate ATS score.
17. Generate warnings and improvement suggestions.

### 15.2 Tailoring Safety

Do:
- Use employer’s language when true.
- Place strongest matching experience first within each role.
- Use exact tool names.
- Mention domain experience if relevant.
- Highlight transferable skills for career changers.

Do not:
- Copy entire JD into resume.
- Add skills user lacks.
- Over-optimize until resume sounds robotic.
- Use hidden/invisible keywords.
- Repeat keywords unnaturally.

- Must include digits.
- Country code recommended.
- Avoid multiple phone numbers unless needed.

- Should be valid URL.
- Recommend clean profile slug.

- Warn if empty or low-quality.

- Each role must have at least 2 bullets.
- Recent role should have 3–6 bullets.
- Avoid duplicate bullets.

Skills:
- Remove duplicates.

- Missing education
- Long unexplained gaps
- Overly designed layout
- Spelling mistakes
- Unprofessional email
- Too many pages

```text
Use standard resume sections, clean formatting, strong action verbs, measurable outcomes, and relevant keywords.
Avoid first-person language, buzzwords, graphics, tables, icons, and sensitive personal data unless requested.
Return the resume in clean markdown with clear section headings.
```

### 23.2 Bullet Rewrite Prompt

```text
Rewrite the following responsibility into a strong resume bullet.
Use this formula: Action verb + task + tools/method + result/impact + scope.
Keep it truthful.
Do not add fake metrics.
If no metric is available, emphasize scope, quality, speed, collaboration, or business value.
Keep the bullet under two lines.
```

### 23.3 ATS Keyword Prompt

```text
Extract ATS keywords from this job description.
Classify them into:
1. Required hard skills
2. Preferred skills
3. Tools/platforms
4. Domain keywords
5. Certifications
6. Soft skills
7. Methodologies
8. Seniority indicators
9. Responsibilities
10. Missing critical keywords the user should confirm
Do not recommend adding a keyword unless the user has evidence for it.
```

### 23.4 Resume Review Prompt

```text
Review this resume for ATS compatibility, recruiter readability, keyword alignment, section completeness, grammar, and impact.
Return:
1. Overall score out of 100
2. ATS score
3. Keyword match score
4. Top strengths
5. Critical issues
6. Missing sections
7. Weak bullets
8. Suggested rewritten bullets
9. Final improvement checklist
```

## 33. Developer Notes

- Keep resume generation modular.
- Store original user facts separately from AI-generated wording.
- Mark generated content vs user-provided content.
- Allow user approval before final export.
- Provide edit controls for each section.
- Always preserve truthfulness over ATS score.
- Keep an ATS-safe template as default.
- Offer premium templates separately, but always provide an ATS-safe version.
- Do not optimize for one ATS vendor only.
- Use job-description matching, not random keyword lists.
- Update role keyword dictionaries regularly using job postings and trusted occupational databases.
